## Install and run on a fresh machine

Use Python 3.9 or later. In a terminal at the extracted folder's top level:

```sh
python -m venv .venv
# macOS/Linux:
source .venv/bin/activate
# Windows PowerShell instead:
# .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python code/verify.py --no-write
python code/run_all.py --smoke
```

The smoke test writes small outputs to a separately printed temporary directory. It exercises the complete workflow but does **not** provide production convergence evidence or overwrite the supplied production results. To choose another isolated output folder:

```sh
python code/run_all.py --smoke --output-dir smoke_output
```

To regenerate every reported experiment, table and figure:

```sh
python code/run_all.py
```

The full run replaces `results/`, `figures/` and `numerical_summary.txt` with newly generated outputs. To preserve the supplied realization/timings, use a different output directory:

```sh
python code/run_all.py --output-dir reproduced_output
```

`FINANCIAL_SDE_OUTPUT_DIR` is also supported. Input/output paths are relative to the script/package, not absolute developer-machine paths. No external market data or network access is required after installing dependencies. Full production includes roughly 1.484 billion non-affine path updates; runtime and memory requirements depend on the machine. Batching keeps fine-increment arrays bounded.

## Parameters and numerical protocol

GBM chosen baseline: `S0=100, mu=0.05, sigma=0.30, T=1`.
Production: 160,000 paths; independent pilot: 20,000; batch 2,000.
Seed: 2026090804; pilot seed: 2026090805.
Grids: `N=8,16,32,64,128,256,512,1024`.
Strong and controlled weak fits: the five finest grids `N=64..1024`.

Non-affine prescribed baseline: `S0=100, Y0=0, mu=0.05, kappa=2, theta=-0.2, xi=0.6, rho=-0.7, sigma_min=0.10, sigma_max=0.50, T=1`, strike 100.
Production: 100,000 paths; batch 512; seed 2026090804.
Coarse grids: `8,16,32,64,128,256`; references: `2048,4096,8192`.
Principal strong fit: `N=8,16,32,64`.
Each coarse increment is the sum of the same finest increments for both drivers. Each grid reruns its states; it does not subsample fine-grid prices. Both log-EM coefficients use old `Y`.

Time unit: years. Price/payoff/error unit: currency units. `Y` is dimensionless. The call quantity is an **undiscounted payoff expectation under the specified drift**, not a risk-neutral option price.

Supplementary evidence: eight independent GBM seed runs with 5,000 production paths and separate 1,000-path pilots; eight non-affine runs with 1,000 paths and reference 8192. The cost study uses 10,000 common paths, a finest Brownian grid of 3072, seven warmed timings per tested grid, and a common terminal L1 target of 0.25. Its additional `N=6` grid is exactly nested in 3072. Seeds, every fitted slope and every timing are in `results/submission_experiments.json`.

Cost is **kernel-only** median wall-clock latency for the NumPy price updates/product, including temporary allocations inside that kernel. It excludes RNG, Brownian aggregation, input/setup preparation, reference evaluation, imports, warm-up, summaries, plotting and file IO. The two selected methods satisfy the same tolerance but do not have identical achieved errors (about 8.3% apart in the supplied run). Timing is not reproducible bit-for-bit and is not a whole-workflow speedup claim.

## Environment and reproducibility

The original production metadata records Windows, Python 3.12.14, NumPy 2.5.3, Matplotlib 3.11.1 and Numba 0.67.0. These recorded versions describe the original run rather than the environment used for cross-platform verification.

Cross-platform verification used macOS arm64, Python 3.9.6, NumPy 2.0.2, Matplotlib 3.9.4 and Numba 0.60.0 in a clean virtual environment. Full production reruns reproduced the displayed scientific results. `requirements.txt` uses compatible ranges so a fresh interpreter can resolve suitable wheels; preserve versions, seeds and batch sizes if comparing exact realizations. Small platform-dependent floating-point changes and different wall-clock times are expected. Numerical verification uses tolerances, not identical file hashes.

The archive includes executable source, unit tests, saved results, figures, report source and the supplied problem pack. It excludes local environments, caches, repository metadata and internal preparation notes.
